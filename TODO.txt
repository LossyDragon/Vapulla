Issues or Bugs
-------------------
- Achievements screen: which achievements are unlocked is wrong (A Hat in Time: 17 / 41 on
  the game page, "0 of 46 unlocked" in the list; 7 Days to Die: 39 / 43 and "43 of 43").
  Found on the emulator: Steam's answer is right, and JavaSteam's
  UserStatsCallback.getExpandedAchievements reads the bit of each achievement from a
  "bit" field the schema does not have, so every achievement of a block gets the unlock
  time of bit 0. The bit is the name of the entry ("bits" { "1" { name, display } ... }).
  In JavaSteam:
      - val bitIndex = bitEntry["bit"].asInteger()
      + val bitIndex = bitEntry.name?.toIntOrNull() ?: bitEntry["bit"].asInteger()
- Every time Vapulla signs in, the friends list of the account's desktop Steam client goes
  offline and comes back as presence arrives. Likely cause: when the friends list arrives,
  JavaSteam's SteamFriends.handleFriendsList sends ClientRequestFriendData for every
  friend by itself; Steam answers without the state and sends the answers to every device
  of the account. Asking for less is not the fix: tried 15 Nov 2026 without Status and
  Presence, every friend lost their avatar instead (Presence carries it), so the flags
  are all back. What should work: JavaSteam not sending that request (an option), and the
  app getting the names and avatars of friends who are offline from
  Player.GetPlayerLinkDetails, which answers only the device that asks
- TryAnotherCM returns to sign-in instead of trying another CM
- Two identical messages in the same second are stored as one
- Downloads skip depots shared from another app (depotfromapp, mostly redistributables)
- Downloads, memory: the heap peaked at 321 to 465 MB of 512 across runs, and the first
  10 s of a download allocate 460 to 740 MB before any chunk arrives. Neither is looked
  at; nothing reads the heap after a download ends
- Code clean-up left over from the review of 15 Nov 2026:
  - Utils is still an object of mixed helpers; its functions could be top-level
  - Profile, Home, Games and the server browser expose several flows, not one UiState
  - Friend chat and group chat still share code by copy (emoticons flow, send failures,
    day headers)
  - The ID decoder decodes in its composable, and the signed-in web page has no view
    model; Diagnostics counts reconnects by the text of the event
  - DownloadManager.move could be a class of its own
  - Screens differ in how they show loading and errors (pull to refresh in some only)
  - README has no screenshots
  - LicenseSync waits 5 seconds before it handles the license list, with no reason given

JavaSteam: left as it is, to look at some day
---------------------------------------------
- A subscriber that throws stops whoever runs the callbacks (CallbackManager lets it
  through, as SteamKit does). Vapulla catches inside its callback loop
- Three ways to wait for an answer, each failing differently: handlers return
  AsyncJobSingle, SteamContent.getManifestRequestCode and getServersForSteamPipe return
  Deferred, SteamAuthTicket.getAuthSessionTicket and generateAccessTokenForApp return
  CompletableFuture. A suspend variant of each would let callers treat them alike
- DepotDownloader has no pause, no cancel for one item and no speed limit. The app closes
  the whole downloader to pause, and throttles by holding up onChunkCompleted
- Leaderboards cannot be listed for an app; the app reads the community XML instead
- A job that times out is still a cancellation (AsyncJobTimeoutException), so awaiting
  one directly ends the coroutine quietly; the app waits through runSuspendCatching

Feature Ideas
----------------------------------------------------
- Remote Clients: install, pause and resume, uninstall and launch a game on another
  machine (ClientComm.InstallClientApp, SetClientAppUpdateState, EnableOrDisableDownloads,
  UninstallClientApp, LaunchClientApp). None has been called yet. The client's side of
  SetClientAppUpdateState is a single "update" flag, so its "action" is most likely 1 to
  carry on and 0 to pause
- Vapulla in the device menu of the desktop client's library (Remote Play clients). What
  it would take, as far as the protos show:
  1. Announce: answer a Discovery with a Status of its own, through
     RemoteClient.SendSteamBroadcastPacket (leave out IP and MAC addresses)
  2. The key: the messages between two devices go through Steam as well
     (RemoteClient.SendSteamToSteamPacket, RemoteClientSteamClient.
     NotifySteamToSteamPacket: source and destination client ID, a "secretid" and an
     encrypted payload). Where a client gets that key, and the cipher, are not known.
     This decides whether the rest can be done
  3. The messages inside (steammessages_remoteclient.proto, message numbers from 9500):
     CMsgRemoteClientAppStatus for the state of each game, CMsgRemoteClientInstallApp
     and its response, status requests and pings. An install can reuse the queue in
     RemoteRequests
  4. A setting to turn it on
  Next: a NetHook capture of the desktop client, started before it signs in, with the
  Steam Deck on; open the device menu of a game and install one on the Deck. In it:
  search for the auth key ID the PC announced (1481747608 on 15 Nov 2026) to find the
  message the key comes in; see whether "secretid" is that ID; and note the order of
  the broadcast and device-to-device packets. A payload of a broadcast packet is bytes
  to NetHookAnalyzer and is read as described under To Verify; the device-to-device
  payload is encrypted before it reaches the CM connection. Without the key in a plain
  message the idea ends there. The open-source in-home streaming clients may also
  document the key
- Vapulla as a remote client: the requests it does not act on yet. Steam also sends a
  client ClientLaunchClientApp (5544) and ClientGetClientDetails (5515), each answered
  with the next message number (steammessages_clientserver_uds.proto in JavaSteam). A
  setting to ask on the phone before a download asked for from elsewhere starts would
  also fit here
- Game notifications and parental settings (read-only)
- Video upload in chat (the uploader accepts WebM / MPEG / OGV)
- Badges: per-game badge levels and community badge progress (Player service)
- From other Steam apps (looked through 16 Nov 2026: GameNative, ArchiSteamFarm, Pluvia,
  UpdogFarmer, SteamTrade, the original Vapulla; taken from the calls their source makes,
  none of it tried here):
  - Game invites from friends: the ClientInviteToGame message, shown as a notification
    or in the chat (GameNative)
  - "Playing elsewhere", with a button to kick the other session: SteamUser's
    kickPlayingSession. The playing session state is already listened for and unused
    (GameNative, UpdogFarmer)
  - Redeem a product key: Store.RegisterCDKey. It changes the account (ArchiSteamFarm,
    UpdogFarmer)
  - Remove a free licence (UserAccount.CancelLicenseForApp) and the list of private apps
    (AccountPrivateApps.GetPrivateAppList) (ArchiSteamFarm)
  - Steam Points: LoyaltyRewards.GetSummary for the balance and QueryRewardItems,
    read-only; goes with the profile decorations (ArchiSteamFarm)
  - Inventory, read-only: Econ.GetInventoryItemsWithDescriptions (ArchiSteamFarm;
    SteamTrade's way through the website no longer works)
  - Family sharing, preferred lender: FamilyGroups.GetPreferredLenders /
    SetPreferredLender, on the Family screen (GameNative)
  - Join or leave a group chat: ChatRoom.JoinChatRoomGroup / LeaveChatRoomGroup
    (ArchiSteamFarm)

DECIDED AGAINST
---------------
- Steam Guard / TwoFactor: too sensitive for accounts, and no push notifications for MFA
- Faster downloads through a native LZMA decoder: on a release build two thirds of the CPU
  time of a download is LZMA decoding in the Java xz library, and only native code (NDK
  here, or binaries shipped by JavaSteam) would cut that much. Set aside on 14 Nov; a
  6.7 GB game takes about 52 s on a Pixel 9 Pro XL as it is
