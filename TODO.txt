Issues or Bugs
-------------------
- Sign-in screen: after the connection is lost while the app is open, it shows
  "Disconnected from Steam" and does not try again by itself once the network is back;
  "Sign in" has to be tapped (it then uses the saved sign-in)
- PICS app access tokens are always requested as 0
- TryAnotherCM returns to sign-in instead of trying another CM
- Database is not cleared on log out
- Friend request notification only opens the app, not the profile
- Two identical messages in the same second are stored as one
- The client connects to a far-away CM server (seen: Buenos Aires from the US); it seems to take
  the first server in the list rather than a near one
- Tapping a download notification opens the app, not the Downloads screen
- Downloads skip depots shared from another app (depotfromapp, mostly redistributables)
- A chat image smaller than the bubble is stretched to its width and looks blurry (seen: a
  96 x 96 image); it should not be drawn larger than the size Steam gives for it
- Downloads, not tried since JavaSteam pools its chunk buffers: pause and resume, remove
  while downloading, losing the network, verify, workshop items, several downloads in a row
- Downloads, memory: the heap peaked at 321 to 465 MB of 512 across runs, and the first
  10 s of a download allocate 460 to 740 MB before any chunk arrives. Neither is looked
  at; nothing reads the heap after a download ends
- Downloads: a paused or queued workshop item is started over, not resumed, when its button
  on the Workshop screen is tapped; resume it from the Downloads screen instead
- Updating a game installed to one storage checks free space on the storage picked in
  Settings, not the one the game is on

- Nicknames: should Steam ever send a ClientPlayerNicknameList with its "incremental" flag
  set, the app would take that short list for the whole list and clear every other
  nickname, because JavaSteam's NicknameListCallback leaves out the message's "incremental"
  and "removal" flags. Not seen to happen; changes arrive through PlayerClient instead.
  setFriendNickname returning a job that can be awaited would let the app wait for
  Steam's answer

- Is "Expired" another EResult that should clear the saved token?

DECIDED AGAINST
---------------
- Steam Guard / TwoFactor: too sensitive for accounts, and no push notifications for MFA
- Faster downloads through a native LZMA decoder: on a release build two thirds of the CPU
  time of a download is LZMA decoding in the Java xz library, and only native code (NDK
  here, or binaries shipped by JavaSteam) would cut that much. Set aside on 14 Nov; a
  6.7 GB game takes about 52 s on a Pixel 9 Pro XL as it is
